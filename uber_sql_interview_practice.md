# Uber Data Science Intern: SQL Interview Practice Guide

Welcome to your comprehensive SQL interview practice guide tailored specifically for **Uber Data Science Intern** roles. The Uber data interview loop heavily focuses on real-world marketplace dynamics, supply-demand balance, pricing mechanics, retention, and operational efficiency.

The problems in this practice guide are built using the **Uber Practice Schema** (`cities`, `riders`, `drivers`, `vehicles`, `trips`, `payments`, `ratings`), covering all core SQL topics required for your interview:
1. **Aggregation & Filtering** (`GROUP BY`, `HAVING`, `CASE` with aggregates)
2. **CTEs & Subqueries** (Modular multi-step queries)
3. **Window Functions** (`ROW_NUMBER()`, `RANK()`, `SUM() OVER(PARTITION BY ...)`, running totals, lag/lead)
4. **Table Joins** (`INNER`, `LEFT`, `RIGHT`, `CROSS` joins)
5. **Date & Time Functions** (`DATE_TRUNC`, interval arithmetic, date formatting, extraction)

---

## Part 1: Schema Overview & Quick Reference

* **`cities`**: Operating markets (`city_id`, `city_name`, `country`, `timezone`)
* **`riders`**: Customer accounts (`rider_id`, `city_id`, `signup_date`, `rider_status`)
* **`drivers`**: Driver partners (`driver_id`, `city_id`, `signup_date`, `driver_status`, `rating`)
* **`vehicles`**: Vehicle details tied to drivers (`vehicle_id`, `driver_id`, `vehicle_type` ['economy','comfort','premium','suv'])
* **`trips`**: Core marketplace transactions (`trip_id`, `rider_id`, `driver_id`, `city_id`, `status` ['completed', 'cancelled_by_rider', 'cancelled_by_driver', 'no_driver', 'in_progress'], `service_type` ['UberX', 'Comfort', 'Black', 'UberXL'], `distance_km`, `duration_minutes`, `fare_amount`, `surge_multiplier`, `requested_at`)
* **`payments`**: Transaction settlement (`payment_id`, `trip_id`, `payment_method`, `payment_status` ['paid', 'refunded', 'failed'], `amount`, `paid_at`)
* **`ratings`**: Two-way feedback (`rating_id`, `trip_id`, `rider_id`, `driver_id`, `rider_rating`, `driver_rating`)

## Part 2: Practice Problems by SQL Topic

### Topic 1: Aggregation, Filtering & Case Clauses

#### Problem 1.1: Marketplace Completion & Cancellation Breakdown
* **Business Context**: Operations teams track trip states to spot marketplace friction. Write a query to find the total number of trip requests and the percentage breakdown of each status (`completed`, `cancelled_by_rider`, `cancelled_by_driver`, `no_driver`) across all cities.
* **SQL Focus**: Aggregate functions, `CASE` statement with aggregate (`SUM(CASE ...)`), percentages.
* **Question**: For every city name, calculate:
  1. Total trip requests.
  2. Percentage of trips that were completed.
  3. Percentage of trips cancelled by riders.
  4. Percentage of trips resulting in `no_driver`.
  Order the results by total requests descending.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    c.city_name,
    COUNT(t.trip_id) AS total_requests,
    ROUND(SUM(CASE WHEN t.status = 'completed' THEN 1 ELSE 0 END) * 100.0 / COUNT(t.trip_id), 2) AS completion_pct,
    ROUND(SUM(CASE WHEN t.status = 'cancelled_by_rider' THEN 1 ELSE 0 END) * 100.0 / COUNT(t.trip_id), 2) AS rider_cancel_pct,
    ROUND(SUM(CASE WHEN t.status = 'no_driver' THEN 1 ELSE 0 END) * 100.0 / COUNT(t.trip_id), 2) AS no_driver_pct
FROM cities c
LEFT JOIN trips t ON c.city_id = t.city_id
GROUP BY c.city_id, c.city_name
ORDER BY total_requests DESC;
```
</details>

#### Problem 1.2: High-Surge Revenue Contribution
* **Business Context**: Surge pricing is triggered when demand outstrips supply. Management wants to know what proportion of total revenue comes from trips with a surge multiplier greater than 1.0.
* **SQL Focus**: Conditional aggregation using `CASE`, grouping, arithmetic.
* **Question**: For each city, calculate total gross fare revenue, surge revenue (sum of fare amounts where `surge_multiplier > 1.0`), and the percentage of total revenue generated by surge pricing.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    c.city_name,
    SUM(t.fare_amount) AS total_revenue,
    SUM(CASE WHEN t.surge_multiplier > 1.0 THEN t.fare_amount ELSE 0 END) AS surge_revenue,
    ROUND(
        SUM(CASE WHEN t.surge_multiplier > 1.0 THEN t.fare_amount ELSE 0 END) * 100.0 / NULLIF(SUM(t.fare_amount), 0), 
        2
    ) AS surge_revenue_pct
FROM cities c
JOIN trips t ON c.city_id = t.city_id
WHERE t.status = 'completed'
GROUP BY c.city_id, c.city_name;
```
</details>

### Topic 2: CTEs (Common Table Expressions) & Subqueries

#### Problem 2.1: Power Riders Analysis
* **Business Context**: Marketing wants to identify loyal riders who take high-value trips. A "Power Rider" is defined as a rider who has completed more than 5 trips *and* whose average trip fare is higher than the overall average fare across all completed trips in the platform.
* **SQL Focus**: Multi-step CTEs, subqueries for global benchmarks.
* **Question**: List the `rider_id`, first and last name, total completed trips, and average fare for all Power Riders. Order by average fare descending.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
WITH global_avg AS (
    SELECT AVG(fare_amount) AS overall_avg_fare
    FROM trips
    WHERE status = 'completed'
),
rider_stats AS (
    SELECT 
        r.rider_id,
        r.first_name,
        r.last_name,
        COUNT(t.trip_id) AS completed_trips,
        AVG(t.fare_amount) AS avg_rider_fare
    FROM riders r
    JOIN trips t ON r.rider_id = t.rider_id
    WHERE t.status = 'completed'
    GROUP BY r.rider_id, r.first_name, r.last_name
)
SELECT 
    rs.rider_id,
    rs.first_name,
    rs.last_name,
    rs.completed_trips,
    ROUND(rs.avg_rider_fare, 2) AS avg_rider_fare
FROM rider_stats rs
CROSS JOIN global_avg g
WHERE rs.completed_trips > 5
  AND rs.avg_rider_fare > g.overall_avg_fare
ORDER BY rs.avg_rider_fare DESC;
```
</details>

#### Problem 2.2: First-Time vs. Repeat Rider Retention Cohorts
* **Business Context**: Growth analysts measure monthly cohorts to monitor user activation. Write a query using CTEs to find each rider's first completed trip month, and then aggregate how many riders signed up or took their first trip in each month.
* **SQL Focus**: Date functions (`DATE_TRUNC` / `DATE_FORMAT`), multi-CTE structuring, filtering first occurrences.
* **Question**: For each calendar month (e.g., 'YYYY-MM' format based on `requested_at`), find the number of unique riders who completed their *very first* trip on Uber that month.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
WITH ranked_trips AS (
    SELECT 
        rider_id,
        requested_at,
        ROW_NUMBER() OVER (PARTITION BY rider_id ORDER BY requested_at ASC) as trip_rank
    FROM trips
    WHERE status = 'completed'
),
first_trips AS (
    SELECT 
        rider_id,
        DATE_FORMAT(requested_at, '%Y-%m') AS first_trip_month
    FROM ranked_trips
    WHERE trip_rank = 1
)
SELECT 
    first_trip_month,
    COUNT(rider_id) AS new_activated_riders
FROM first_trips
GROUP BY first_trip_month
ORDER BY first_trip_month ASC;
```
</details>

### Topic 3: Window Functions (`OVER`, `PARTITION BY`, Ranking, Running Totals)

#### Problem 3.1: Top 3 Drivers by Revenue per City
* **Business Context**: Operations awards bonuses to top-performing drivers in each city monthly. 
* **SQL Focus**: Window ranking functions (`RANK()`, `DENSE_RANK()`, `ROW_NUMBER()`), `PARTITION BY`.
* **Question**: Write a query to rank drivers within each city based on their total completed trip fare revenue. Return the city name, driver ID, driver name, total revenue, and their rank within the city. Restrict the output to the top 3 drivers per city.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
WITH driver_city_revenue AS (
    SELECT 
        c.city_name,
        d.driver_id,
        CONCAT(d.first_name, ' ', d.last_name) AS driver_name,
        SUM(t.fare_amount) AS total_revenue
    FROM drivers d
    JOIN cities c ON d.city_id = c.city_id
    JOIN trips t ON d.driver_id = t.driver_id
    WHERE t.status = 'completed'
    GROUP BY c.city_id, c.city_name, d.driver_id, d.first_name, d.last_name
),
ranked_drivers AS (
    SELECT 
        city_name,
        driver_id,
        driver_name,
        total_revenue,
        RANK() OVER (PARTITION BY city_name ORDER BY total_revenue DESC) as revenue_rank
    FROM driver_city_revenue
)
SELECT 
    city_name,
    driver_id,
    driver_name,
    ROUND(total_revenue, 2) AS total_revenue,
    revenue_rank
FROM ranked_drivers
WHERE revenue_rank <= 3
ORDER BY city_name, revenue_rank;
```
</details>

#### Problem 3.2: Cumulative Running Total of Fares per Driver
* **Business Context**: Financial auditing requires tracking running totals of gross earnings for drivers chronologically.
* **SQL Focus**: Window frame clause (`SUM() OVER (PARTITION BY ... ORDER BY ...)`).
* **Question**: For a specific driver (`driver_id = 101`), list every completed trip with its `trip_id`, `requested_at`, individual `fare_amount`, and a running total of fare earnings up to that trip.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    trip_id,
    requested_at,
    fare_amount,
    SUM(fare_amount) OVER (
        PARTITION BY driver_id 
        ORDER BY requested_at ASC 
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS cumulative_earnings
FROM trips
WHERE driver_id = 101 
  AND status = 'completed'
ORDER BY requested_at ASC;
```
</details>

### Topic 4: Advanced Joins (`LEFT`, `RIGHT`, `CROSS`, `INNER`)

#### Problem 4.1: Identifying Inactive Drivers (Left Join Trap)
* **Business Context**: We want to identify drivers who have *never* completed a trip since signing up.
* **SQL Focus**: `LEFT JOIN` combined with `IS NULL` checking, filtering in `WHERE` vs `ON`.
* **Question**: Write a query to find all drivers (`driver_id`, email, signup date) who have zero completed trips in the `trips` table.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    d.driver_id,
    d.first_name,
    d.last_name,
    d.email,
    d.signup_date
FROM drivers d
LEFT JOIN trips t ON d.driver_id = t.driver_id AND t.status = 'completed'
WHERE t.trip_id IS NULL;
```
</details>

#### Problem 4.2: Cross Join for City Service-Type Matrix
* **Business Context**: Product strategy needs a complete matrix of all operating cities paired with every possible service type (`UberX`, `Comfort`, `Black`, `UberXL`), even if zero trips have been conducted for a specific combination.
* **SQL Focus**: `CROSS JOIN`, pairing dimensions, outer matching.
* **Question**: Generate a table showing every combination of city and service type, along with the actual count of completed trips for that combination (returning 0 if none exist).

<details>
<summary><b>Click to view Solution</b></summary>

```sql
-- Generate distinct service types inline or via subquery
WITH service_types AS (
    SELECT DISTINCT service_type FROM trips
),
city_services AS (
    SELECT c.city_id, c.city_name, st.service_type
    FROM cities c
    CROSS JOIN service_types st
)
SELECT 
    cs.city_name,
    cs.service_type,
    COUNT(t.trip_id) AS completed_trips_count
FROM city_services cs
LEFT JOIN trips t ON cs.city_id = t.city_id 
                 AND cs.service_type = t.service_type 
                 AND t.status = 'completed'
GROUP BY cs.city_id, cs.city_name, cs.service_type
ORDER BY cs.city_name, cs.service_type;
```
</details>

### Topic 5: Date, Time & Interval Functions

#### Problem 5.1: Hourly Surge and Demand Patterns
* **Business Context**: Demand spikes during rush hours. Marketplace pricing relies on understanding trip request volume by hour of the day.
* **SQL Focus**: Extracting hour from datetime (`EXTRACT(HOUR FROM ...)` or `HOUR(...)`), aggregation.
* **Question**: Write a query to find the total number of trip requests and the average surge multiplier for each hour of the day (0 through 23) across all cities. Order by hour.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    HOUR(requested_at) AS request_hour,
    COUNT(trip_id) AS total_requests,
    ROUND(AVG(surge_multiplier), 2) AS avg_surge_multiplier
FROM trips
GROUP BY HOUR(requested_at)
ORDER BY request_hour ASC;
```
</details>

#### Problem 5.2: Trip Fulfillment Speed (Request to Pickup Time)
* **Business Context**: Dispatch latency is a core KPI. Riders cancel if pickup takes too long.
* **SQL Focus**: Time difference calculation (`TIMESTAMPDIFF(MINUTE, start, end)`), filtering out null timestamps.
* **Question**: Calculate the average fulfillment duration (in minutes) from `requested_at` to `pickup_at` for all completed trips, broken down by city and service type. Exclude trips where timestamps are missing.

<details>
<summary><b>Click to view Solution</b></summary>

```sql
SELECT 
    c.city_name,
    t.service_type,
    COUNT(t.trip_id) AS completed_trips_count,
    ROUND(AVG(TIMESTAMPDIFF(MINUTE, t.requested_at, t.pickup_at)), 1) AS avg_dispatch_minutes
FROM trips t
JOIN cities c ON t.city_id = c.city_id
WHERE t.status = 'completed'
  AND t.requested_at IS NOT NULL 
  AND t.pickup_at IS NOT NULL
GROUP BY c.city_id, c.city_name, t.service_type
ORDER BY avg_dispatch_minutes DESC;
```
</details>

## Part 3: Interview Tips for Uber Data Science Roles

1. **Clarify Edge Cases First**: Always ask about null values (`driver_id` can be NULL if a trip results in `no_driver`), cancelled trips, and timezone handling.
2. **Performance Considerations**: Mention indexing when discussing queries with large data volume (`trips` table indexed on `(city_id, requested_at)` and `driver_id`).
3. **Marketplace Mentality**: When writing SQL queries, connect your findings back to rider retention, driver supply shortages, pricing elasticity, and platform liquidity.
